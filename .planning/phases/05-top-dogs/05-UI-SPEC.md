## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#fbf9f8` (`bg-surface`) | Page background — already set on history page wrapper |
| Secondary (30%) | `#ffffff` (`bg-surface-container-lowest`) | Top Dogs card background |
| Accent (10%) | `#9b4500` (`text-primary`) | "Most Liked" label, count number, "Top Dogs" section heading |
| Dislike semantic | `#ba1a1a` (`text-error`) | "Most Disliked" label and dislike count number |

Accent reserved for: "Most Liked" card label, like count number, "Top Dogs" section heading. These are the ONLY elements that receive `text-primary`.

"Most Disliked" card label and its count number use `text-error` (#ba1a1a) — this is semantic differentiation, not destructive action. There are no destructive actions in this phase.

Source: CLAUDE.md Design System, REQUIREMENTS.md TOP-04, CONTEXT.md D-05, D-08.

## Component Inventory

### TopDogsSection (new — `components/TopDogsSection.tsx`)

**Props:**
```ts
interface TopDogsProps {
  topDogs: {
    mostLiked: { dogId: string; imageUrl: string; likeCount: number } | null;
    mostDisliked: { dogId: string; imageUrl: string; dislikeCount: number } | null;
  } | null;
}
```

**Layout:**
- Outer wrapper: `mb-lg` bottom margin to separate from HistoryList below
- Section heading: `text-headline-md text-on-surface font-bold mb-md` — text: "Top Dogs"
- Card grid: `grid grid-cols-2 gap-md` — always 2 columns on all screen sizes (D-06)
- When both cards are null: single-column message replaces grid (see Empty State below)
- When only one card is null: render only the real card; do not render a placeholder (D-03)

**Card anatomy (per card):**
- Container: `bg-surface-container-lowest rounded-[24px] shadow-[0_4px_24px_rgba(0,0,0,0.04)] overflow-hidden flex flex-col`
- Dog image: `relative w-full` with fixed height `h-[140px]`, `<Image fill className="object-cover" />`
- Info strip: `p-sm flex flex-col gap-xs` (12px padding, 4px row gaps)
  - Card label row: `text-label-lg` — "Most Liked" in `text-primary`, "Most Disliked" in `text-error`
  - Dog ID row: `text-label-lg text-on-surface-variant` — `#{dogId.slice(0, 8)}`
  - Count row: `<span class="text-headline-md text-primary">{count}</span><span class="text-body-md text-on-surface-variant"> likes</span>` for liked card; `text-error` for count on disliked card

Source: CONTEXT.md D-05, D-06, D-07, D-08, REQUIREMENTS.md TOP-03, TOP-04.

## Interaction Contract

### TopDogsSection states

| State | Trigger | UI Response |
|-------|---------|-------------|
| Both cards present | `topDogs.mostLiked != null && topDogs.mostDisliked != null` | Render 2-column grid with both cards |
| One card present | One category is null | Render only the non-null card in the grid; no placeholder for missing card |
| Both cards null | `swipes.json` empty or no swipes | Render empty state message inside section — do NOT hide section |
| Image load error | Next.js `<Image>` unoptimized source fails | Next.js default broken-image rendering — no custom error handler required this phase |

No hover effects, click handlers, or transitions on Top Dogs cards — they are display-only in Phase 5.

Source: CONTEXT.md D-03, D-04.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Section heading | "Top Dogs" |
| Most Liked card label | "Most Liked" |
| Most Disliked card label | "Most Disliked" |
| Like count | "{N} likes" — number in `text-headline-md`, " likes" in `text-body-md` |
| Dislike count | "{N} dislikes" — number in `text-headline-md`, " dislikes" in `text-body-md` |
| Dog ID display | "#{dogId.slice(0, 8)}" — first 8 chars, prefixed with # (matches HistoryList pattern) |
| Empty state (both null) | Heading: "No top dogs yet" / Body: "No swipes yet — start swiping to see top dogs!" |
| Error state | Not in scope for Phase 5 — `getTopDogs()` is called server-side; if it throws, Next.js error boundary handles it |

Source: CONTEXT.md D-04 (empty message exact wording), D-05 (count format spec). Dog ID pattern from existing `HistoryList.tsx` line 168 / 207.

No destructive actions exist in this phase. No confirmation dialogs required.

## Layout Integration

`TopDogsSection` is inserted into `app/history/page.tsx` as a sibling above `<HistoryList />`:

```
<div className="max-w-7xl mx-auto px-container-padding md:px-xl pt-lg">
  <div className="flex flex-col md:flex-row ...">  {/* existing title block */}
    ...
  </div>
  <TopDogsSection topDogs={topDogs} />   {/* NEW — inserted here */}
  <HistoryList records={records} currentUser={...} />
</div>
```

The `TopDogsSection` receives no sticky positioning — it scrolls with the page content. The existing sticky SummaryBar inside `HistoryList` remains at `top-16` on mobile and `top-0` on desktop — unchanged.

Source: CONTEXT.md code_context integration point, `app/history/page.tsx` examined structure.

## API Route Contract

`app/api/stats/route.ts` — new file, no auth guard (public endpoint per CONTEXT.md D-02):

- Method: GET
- Response shape: `{ mostLiked: { dogId, imageUrl, likeCount } | null, mostDisliked: { dogId, imageUrl, dislikeCount } | null }`
- Returns `NextResponse.json(result)` where `result = await getTopDogs()`
- No UI rendered by this route — it is a data endpoint only (TOP-02)
