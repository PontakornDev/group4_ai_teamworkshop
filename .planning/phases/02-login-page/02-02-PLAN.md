<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → /api/auth/[...nextauth] | Untrusted OAuth callback parameters (code, state) arrive here |
| /api/auth/* → process.env | Secrets (CLIENT_SECRET, NEXTAUTH_SECRET) cross from environment into NextAuth runtime |
| Session cookie → protected pages | NextAuth session JWT in httpOnly cookie crosses to server-side `auth()` call |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02b-01 | Spoofing | /api/auth/[...nextauth] OAuth callback | mitigate | NextAuth v5 validates OAuth `state` parameter on every callback — CSRF protection built into the handler; no custom code needed |
| T-02b-02 | Tampering | NextAuth session JWT cookie | mitigate | Cookie is signed with `NEXTAUTH_SECRET` — tampering invalidates the signature; secret must be strong and stored only in `.env.local` |
| T-02b-03 | Information Disclosure | CLIENT_SECRET / NEXTAUTH_SECRET in env | mitigate | Values stored in `.env.local` (not committed); `.env.local.example` committed instead (per D-03); `.gitignore` excludes `.env.local` |
| T-02b-04 | Elevation of Privilege | app/swipe/page.tsx auth guard | mitigate | Guard uses server-side `auth()` (per D-05) — cannot be bypassed from client; `useSession()` client guards are NOT used for protection per D-05 |
| T-02b-05 | Denial of Service | random.dog API dependency | accept | Out of scope for auth phase; handled in Phase 1 retry logic |
</threat_model>
